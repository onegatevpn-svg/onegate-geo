# onegate-geo

Свои geo-базы для маршрутизации в Happ. Собираются здесь, раздаются через
jsDelivr — без своего домена, без сервера, без оплаты.

```
https://cdn.jsdelivr.net/gh/ВЛАДЕЛЕЦ/onegate-geo@release/geosite.dat
https://cdn.jsdelivr.net/gh/ВЛАДЕЛЕЦ/onegate-geo@release/geoip.dat
```

## Зачем

Раньше профиль маршрутизации тянул базы из чужого репозитория. Это значило,
что посторонний человек решает, какие домены попадают в `category-ru`,
`whitelist` и `direct` — то есть какой трафик у наших клиентов идёт **мимо
туннеля, в открытую**. Плюс его имя было видно в настройках приложения.

## Что внутри

| файл | что делает |
|---|---|
| `profile.json` | список категорий, попадающих в `geosite.dat` (режим `allowlist` штатного генератора v2fly) |
| `data/onegate-direct` | наши домены, которые обязаны ходить напрямую — госуслуги, банки, операторы. Замена нестандартной категории `geosite:whitelist` |
| `data/onegate-torrent` | трекеры. Замена `geosite:torrent`, которой нет в публичном источнике |
| `geoip/private-ranges.txt` | приватные и служебные диапазоны → `geoip:private` |
| `build-geoip.py` | собирает `geoip.dat` из текстовых списков CIDR. Без Go и без ключа MaxMind — формат protobuf закодирован вручную |
| `routing-profile.json` | сам профиль Happ, шаблон |
| `make-routing-link.py` | превращает профиль в `happ://routing/add/…` и печатает готовые команды для панели |
| `.github/workflows/build.yml` | ежедневная пересборка, публикация в ветку `release`, сброс кэша jsDelivr |

## Как запустить в первый раз

1. Создать на GitHub **публичный** репозиторий `onegate-geo` — jsDelivr раздаёт
   только публичные.
2. Залить сюда содержимое этой папки, ветка `main`.
3. Settings → Actions → General → Workflow permissions → **Read and write**.
4. Вкладка Actions → workflow «build geo» → Run workflow.
5. Проверить размеры в логе шага «Проверить результат».
6. Сгенерировать ссылку и выполнить напечатанные команды на сервере подписки:

```
python3 make-routing-link.py --repo ВЛАДЕЛЕЦ/onegate-geo --onadd
```

`--onadd` нужен ровно один раз, при первой раскатке: он активирует новый
профиль, даже если у клиента активен старый. Дальше — без него.

## Категории, которых нет в публичном источнике

`win-spy`, `torrent`, `twitch-ads`, `whitelist` в `v2fly/domain-list-community`
отсутствуют — они из сборки Loyalsoldier и из самодельных списков. Здесь
`torrent` и `whitelist` заменены своими файлами, `win-spy` и `twitch-ads`
выброшены. Если понадобятся — завести файлами в `data/` и дописать в
`profile.json`.

## Про размер

Ориентиры на сентябрь 2026:

```
geosite.dat   публичный полный (Loyalsoldier)   11 МБ
              прежний, из чужой сборки          68 КБ
              у конкурента NETZRUN              17 КБ
geoip.dat     прежний, из чужой сборки         430 КБ
              у конкурента NETZRUN             917 КБ
              наш (ru + private)               131 КБ
```

Размер имеет значение: ядро Xray на iOS живёт в лимите около 50 МБ, и полные
базы туда не влезают. Если после сборки `geosite.dat` окажется великоват —
резать надо **список категорий** в `profile.json`, а не файл. Основной вес
даёт `category-ads-all`: она тянет за собой дерево из двух сотен файлов.

## Обновления и защита от них

Upstream не зафиксирован: каждая сборка тянет свежий `v2fly/domain-list-community`
и свежие диапазоны РФ. Это значит ноль обслуживания — новые домены приезжают
сами, вспоминать о них не надо.

Чтобы «само» не означало «вслепую», перед публикацией сборка сверяется с
предыдущей. Категории из `watch-lists.txt` выгружаются в плоский вид,
считаются записи и сравниваются с `counts.txt` прошлого выпуска. Если
категория исчезла или просела больше чем на 20 % — сборка падает и **ничего
не публикует**, прошлый выпуск остаётся жить. Так поломка наверху не доедет
до клиентов молча.

Если просадка ожидаемая (категорию наверху осознанно почистили) — просто
перезапустить workflow вручную после правки `watch-lists.txt` или порога.

### Откат

Ветка `release` ведётся с историей, каждый выпуск — отдельный коммит. Откат
не требует пересборки: достаточно навести профиль на конкретный коммит,
jsDelivr это умеет.

```
https://cdn.jsdelivr.net/gh/ВЛАДЕЛЕЦ/onegate-geo@<хэш коммита>/geosite.dat
```

Пересобрать ссылку профиля и выполнить команды из `make-routing-link.py`.

## Правило, которое легко нарушить

Категория, на которую ссылается профиль, обязана существовать в собранной базе.
Если сослаться на отсутствующую — правило **молча** не сработает: ни ошибки, ни
предупреждения, трафик просто уедет по маршруту по умолчанию. Поэтому
`profile.json` и `routing-profile.json` правятся всегда вместе.
