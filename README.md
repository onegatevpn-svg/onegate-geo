# onegate-geo

Geo-базы для маршрутизации в Happ. Собираются здесь, раздаются через jsDelivr.

```
https://cdn.jsdelivr.net/gh/onegatevpn-svg/onegate-geo@release/geosite.dat
https://cdn.jsdelivr.net/gh/onegatevpn-svg/onegate-geo@release/geoip.dat
```

## Установка

1. Создать на GitHub **публичный** репозиторий `onegate-geo` — jsDelivr раздаёт только публичные.
2. Залить сюда содержимое этой папки в ветку `main`. Проверить, что видна папка `.github/workflows`.
3. Settings → Actions → General → Workflow permissions → **Read and write** → Save.
4. Actions → «build geo» → Run workflow.
5. Сгенерировать ссылку профиля и выполнить напечатанные команды на сервере подписки:

```
python3 make-routing-link.py --onadd
```

`--onadd` нужен один раз, при первой раскатке: он активирует профиль, даже если у клиента активен другой. Дальше — без него.

## Как вносить изменения

Дописал домен в `data/onegate-direct` или `data/onegate-torrent`, запушил в `main` — сборка стартует сама. Приложения подтянут новые базы в течение недели.

Список категорий, попадающих в `geosite.dat`, — в `profile.json`. Он и `routing-profile.json` правятся **всегда вместе**: если профиль ссылается на категорию, которой нет в базе, правило молча не сработает — ни ошибки, ни предупреждения, трафик уедет по маршруту по умолчанию.

## Что внутри

| файл | что делает |
|---|---|
| `profile.json` | какие категории попадают в `geosite.dat` |
| `data/onegate-direct` | домены, которые обязаны ходить напрямую — госуслуги, банки, операторы |
| `data/onegate-torrent` | трекеры, идут в блок |
| `geoip/private-ranges.txt` | приватные диапазоны → `geoip:private` |
| `watch-lists.txt` | категории, за размером которых следит сборка |
| `build-geoip.py` | собирает `geoip.dat` из списков CIDR |
| `routing-profile.json` | профиль Happ, шаблон |
| `make-routing-link.py` | делает из профиля `happ://routing/add/…` и печатает команды для панели |
| `.github/workflows/build.yml` | ежедневная пересборка и публикация |

## Обновление и откат

Сборка идёт раз в сутки, а также при каждом коммите в `main`. Берёт свежие исходники, кладёт результат в ветку `release`, сбрасывает кэш jsDelivr.

Перед публикацией сверяется с предыдущим выпуском: категории из `watch-lists.txt` пересчитываются, и если какая-то исчезла или просела больше чем на 20 % — сборка падает и ничего не публикует. Прошлый выпуск продолжает работать.

Откат не требует пересборки. Ветка `release` ведётся с историей, поэтому достаточно навести профиль на нужный коммит:

```
https://cdn.jsdelivr.net/gh/onegatevpn-svg/onegate-geo@<хэш>/geosite.dat
```

## Ограничение по размеру

Ядро Xray на iOS живёт в лимите около 50 МБ, полные публичные базы туда не влезают. Сборка падает, если файл вышел больше 3 МБ. Если `geosite.dat` окажется великоват — резать надо список категорий в `profile.json`, а не файл. Основной вес даёт `category-ads-all`.

## Категории, которых нет в источнике

`win-spy`, `torrent`, `twitch-ads`, `whitelist` в `v2fly/domain-list-community` отсутствуют. `torrent` и `whitelist` заменены своими файлами, `win-spy` и `twitch-ads` не используются. Понадобятся — завести файлом в `data/` и дописать в `profile.json`.
